# Estrategia de pruebas

- `tests/Unit`: dominio y cálculos. `tests/Architecture`: límites de módulos (bloqueante en CI). `tests/Integration`: API, BD, storage, colas. `tests/Contract`: adapters SUNAT/PSE/OSE contra el simulador. `tests/Security`: autorización y aislamiento cross-tenant. `tests/Performance`, `tests/E2E`.
- **CI** (`.github/workflows/ci.yml`, GitHub Actions): restauración con `--locked-mode`, compilación en **Release** (donde las advertencias son errores: una prueba que compila en Debug puede romper el CI), pruebas unitarias, de arquitectura, de seguridad/API (Testcontainers) e integración, paquetes vulnerables, SBOM, gitleaks y construcción y escaneo con Trivy de las imágenes de la API y de los workers. Las acciones de terceros van fijadas a un commit. Antes de subir, `dotnet build SecureFact.slnx -c Release` y las pruebas dan el mismo resultado que el CI.
- **Cobertura**: `dotnet build SecureFact.slnx -c Release`, luego `dotnet test SecureFact.slnx -c Release --no-build --settings coverage.runsettings --collect:"XPlat Code Coverage" --results-directory coverage-results` y `dotnet tool restore && dotnet tool run reportgenerator -reports:"coverage-results/**/coverage.cobertura.xml" -targetdir:coverage -reporttypes:"TextSummary;HtmlInline;JsonSummary;Cobertura" -assemblyfilters:"+SecureFact.*"`; el informe queda en `coverage/` (`Summary.txt` y `index.html`). El CI hace lo mismo y falla si las líneas bajan de 95 % o las ramas de 84 % (`MIN_LINE_COVERAGE` y `MIN_BRANCH_COVERAGE` en `ci.yml`). Los pisos son un trinquete: se suben cuando la cobertura sube y no se bajan para dejar pasar un cambio. La cobertura es una señal de lo que ninguna prueba toca, no una medida de calidad: las pruebas de aislamiento entre inquilinos y de reglas de SUNAT se escriben por el riesgo, no por el porcentaje.
- **Extremo a extremo de la interfaz** (`web/e2e/`, Playwright, ADR-040): 57 recorridos contra la API real, PostgreSQL, S3, los workers y el simulador de SUNAT (ADR-039); trabajo `e2e` del CI. Cada prueba crea su propia cuenta por la API. Cómo correrlas: `web/README.md`.
- Sin FluentAssertions (licencia comercial en v8): se usa `Assert` de xUnit.
- Servicio beta de SUNAT solo para estructura XML en Staging; carga y resiliencia con el simulador interno.
