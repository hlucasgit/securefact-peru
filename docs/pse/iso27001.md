# Preparación ISO/IEC 27001

Requisito PSE (S01). Se prepara desde el inicio para reutilizar evidencia. Mapa de lo que ya produce el proyecto (control específico del Anexo A por confirmar con el auditor; no se citan números de control de memoria):

| Área SGSI | Qué existe / se creará | Dónde |
|-----------|------------------------|-------|
| Inventario de activos | Registro de activos (código, datos, infraestructura, proveedores) | `docs/compliance/asset-inventory.md` (Fase 1) |
| Clasificación de información | Niveles (Público, Interno, Confidencial, Secreto: certificados, claves SOL) | `docs/security/information-classification.md` |
| Gestión de accesos | RBAC con permisos explícitos, MFA, revocación, revisión periódica | módulo Identity |
| Incidentes | Runbooks y plantilla de postmortem | `docs/operations/runbooks/` |
| Backups y continuidad | RPO/RTO, PITR, pruebas de restore | `docs/operations/backup-restore.md` |
| Proveedores | Registro de proveedores (cloud, PSE/OSE, correo) | `docs/compliance/supplier-register.md` |
| Cambios | PR + ADR + CI obligatorio; changelog | `CONTRIBUTING.md` |
| Vulnerabilidades | Dependabot/Renovate, SCA, escaneo de contenedores, gitleaks, SBOM | CI |
| Riesgos | Registro de riesgos | `docs/compliance/risk-register.md` |
| Logs/auditoría | Logging estructurado, `audit.event` append-only con hash encadenado | módulo Audit |
| Auditorías internas | Calendario y evidencias | `evidence-register.md` |

Acciones futuras: seleccionar organismo certificador acreditado, definir alcance (plataforma CPE), declaración de aplicabilidad, auditoría interna, revisión por la dirección.
